# Personal Cortex 接手评审：先辨识机制，再训练控制器

日期：2026-11-09。起点：`36a0be9`。这是首轮文献调研、代码审计和实验协议推进，**不是已经完成 B1.3 神经控制器验证**。

本轮实际运行的数据及解释见 [B1_3_PILOT_RESULTS.md](B1_3_PILOT_RESULTS.md)。

后续进展：本文写作后，真实 MLP/GRU 控制器已实现并完成独立留出评估，见[控制器协议](B1_3_CONTROLLER_PROTOCOL.md)及[结果报告](B1_3_CONTROLLER_RESULTS.md)。下文“待实施方案”保留为当时的研究计划，不应理解为当前仍没有控制器代码；已完成的实验仍未证明主指标优于调优基线。

## 1. 优先研究什么

将当前问题明确为：**部分可观测、非平稳用户状态的在线滤波，以及滤波更新规则的元学习**。

需要分别维护：

- 长期偏好 `z_t`，它可能漂移；
- 当前轮指令 `u_t`，它可以覆盖本轮输出，但不必改变长期偏好；
- 报告/纠正 `o_t`，它可能缺失、错误或没有说明适用范围；
- 对偏好的信念分布 `b_t(z)`，而不只是单个确定值。

因此，惊讶高不等于证据可靠：一次强冲突可能来自真正漂移、临时要求、解析错误或恶意/随机噪声。网络必须利用可观测证据区分这些解释，不能通过模拟器给的事件标签直接获得答案。

### 一个需要纠正的概念

B1.2 中所谓 Hebbian 更新为：

`w_new = decay * (1 - eta) * w_old + eta * one_hot(report)`。

这是**带衰减的类别 delta rule / 指数加权证据**。没有可训练的神经元交互或学习出的控制器。它的机制价值值得保留，但小幅胜过 Latest 不能等同于“神经记忆已经胜出”。Delta rule 本身也可看作平方误差的一步梯度更新，因此“局部规则 vs 梯度”不是这里可靠的二分法。

### 可观测性边界

若一个二元偏好的临时反转独立出现、没有任何语言范围标记，那么对只有报告值的学习器，它与观测噪声可能统计等价。例如临时反转率为 `tau`，对当前目标的报告噪声率为 `epsilon`，对长期状态的等效反转率是：

`epsilon_eff = tau * (1 - epsilon) + (1 - tau) * epsilon`。

在这种设定下，要求系统逐次识别“这是临时需求还是错误反馈”是不合理的；它可以学到风险最小的滤波策略，但无法恢复根本没被观测到的信息。本轮分别提供范围可见与不可见两个场景，避免把这个差别藏起来。

## 3. 代码审计：B1.2 的具体问题

重点文件：`src/personal_cortex_lab/run_b1_2_memory.py`。

1. 文件开头承诺 IDENTICAL feedback，但第 145–152 行根据候选自己的回答错误生成反馈。候选状态不同就会改变未来观测，不能当成共同轨迹机制对照。
2. 任务抽样、回答噪声和反馈共用 RNG，条件分支会改变随机数消耗；即使 seed 一样，也不保证候选接收同一个任务序列。
3. `ContextMLP` 没有 MLP、优化器或训练阶段；累计计数不实现注释中的 10 轮窗口，超过门槛的历史值以后可一次重写。
4. `false_update` 的分子是错误报告条目数，分母却是有报告的轮数；它既不是写坏记忆的比例，量纲也不一致。
5. 用漂移后第一个完整答对的回答作为恢复标准，会受执行器随机性和任务抽样影响；`if recov` 还漏掉零延迟恢复。
6. 临时偏好替换 `true_p`，没有单独保留长期状态，也没有把本轮明确指令提供给预测接口，混淆了长期记忆与指令遵循。
7. `create` 强制长回答，导致部分 `verbosity` 漂移被覆盖；`format` 由任务名固定，可能让模型学到模拟器捷径。
8. 每一维 85% 遵循率下，即使三维记忆完全正确，整条回答错误率仍为 `1 - 0.85^3 = 0.385875`。因此应以状态指标研究记忆，以生成指标单独研究执行器。

README/ARCHITECTURE 中“不必走梯度”“Hypernet 不仅更快”等仍是早期探索性叙述，不应当作已验证的结论。新协议独立新增，未改写旧脚本和旧结果。

## 4. 本轮落地：B1.3 协议 pilot

### 已实现

- `replay.py`：不可变公开观测与评估私有真值分离；候选无关的稀疏报告、噪声、任务和漂移；轨迹可序列化回放。
- `replay_baselines.py`：NoMemory、Global-Latest、Context-Latest、折扣 Dirichlet 计数、Delta/EMA、有限状态 HazardFilter。
- `run_b1_3.py`：先预测后观察、实际硬预测损伤、概率质量指标、持续恢复与未恢复记录、按种子聚类的配对 bootstrap、完整轨迹/预测/来源哈希。
- `tests/test_b1_3.py`：复现性、真值隔离、范围处理、漂移实际发生、更新损伤、恢复删失、概率归一化、统计层级等回归测试。

**报告是外生的结构化偏好陈述，不是由候选回答错误触发的闭环纠正。** 每轮每个维度独立以 `feedback_prob` 报告；报告出现后以 `noise_prob` 给出错误值。噪声概率含义不同于 B1.2 的每轮额外插入错误条目，不能直接比较两轮的绝对分数。

这可以隔离更新机制，但还不能代表用户在真实交互中的反馈选择偏差。后续必须另做闭环评估，不能把两者混在同一张性能表里。

### 场景

| 场景 | 报告概率/维度 | 条件噪声率 | 长期变化 | 临时反转 |
| --- | --- | --- | --- | --- |
| stationary_clean | 0.3 | 0 | 无 | 无 |
| sparse_noise | 0.3 | 0.2 | 一次反转 | 无 |
| aba | 0.5 | 0.05 | A→B→A | 无 |
| transient_scoped | 0.5 | 0.05 | 无 | 15% 轮次；范围可见 |
| transient_unscoped | 0.5 | 0.05 | 无 | 相同反转；范围不可见 |

每个用户的每个任务随机分配三维偏好；不再让任务名直接决定格式。漂移改变所有任务的 verbosity，不被覆盖；时点按用户随机扰动。两个临时场景共享环境和报告值，仅可见范围不同。范围可见时，所有方法用相同的公共处理：本轮 instruction 覆盖生成目标，`scope=turn` 的报告不写入长期状态。这个能力是接口规则，**不是神经网络学出来的**。

### HazardFilter 是什么

对每个任务/维度维护类别信念 `b`。相隔 `delta` 个全局轮次后：

`b_prior = (1-hazard)^delta * b + (1-(1-hazard)^delta) * uniform`。

若有报告，用固定对称噪声似然做 Bayes 更新；缺失不当作赞同。它是有限状态 HMM 滤波，不维护 run-length 后验。`hazard=0.01, noise=0.1` 是预先固定的模型假设，并未从测试场景配置读取真实噪声率或漂移时刻。

本轮折扣计数和 Delta 的超参数也固定，未经过公平验证集调优，不能把这次比较当作已击败“最强贝叶斯基线”。

### 信息和容量公平到什么程度

所有方法获得完全相同的任务、时间、反馈和可见指令。上下文方法最多使用 4×3 个逻辑槽，不允许额外保存无限历史。**逻辑槽数相同不等于字节预算相同**：

| 方法 | 最大动态状态（概念计数，非 Python 实际字节） |
| --- | --- |
| NoMemory | 0 |
| Global-Latest | 3 个类别值 |
| Context-Latest | 12 个类别值 |
| Context-DiscountedCounts | 28 个类别计数 + 4 个时间戳 |
| Context-Delta | 28 个类别权重 |
| Context-HazardFilter | 28 个类别概率 + 4 个时间戳 |

Global/NoMemory 仅作参照，不用于宣称等容量优势。正式神经实验还需记录控制器参数、每用户状态字节、训练/推断耗时，并加入等状态预算消融。

### 指标及统计约定

- `hidden_acc`：观察本轮反馈**之前**，当前任务三维长期状态的硬预测准确率，主指标。
- `joint_state_error`：三维中任意一维长期状态错误的轮次比例，没有混入生成器噪声。
- `expected_mock_answer_error`：解析计算 B1.2 式独立维度执行噪声下的期望错误率；含当前可见指令，不使用采样，**不是真实 LLM 测试**。
- `nll` / `brier`：长期状态概率评分。Latest 的 one-hot 在错误时 NLL 截断到 `-log(1e-12)`；这些确定性基线没有校准，不能仅凭 NLL 差距宣称预测能力突破。
- `harmful_writes`：观察反馈后，当前任务某维的硬预测从正确变错误的实际次数。
- `harmful_write_rate`：上述次数 / 当前任务硬预测发生变化的次数；无变化为 0。它不衡量置信度被轻微污染，也不计 Global 写入对其他任务的连带影响。必须同时看写入数和准确率，不能用“不写所以不受损”取胜。
- `recovery_rate`：各受漂移影响的任务/维度，达到连续 **3 次该任务访问**预测正确的事件比例；记录完成时的全局轮次和任务访问数。下一次同槽漂移或 episode 结束时仍未恢复的事件保留为删失记录，不能只平均成功恢复者。
- 同分时所有方法采用相同固定类别次序；用户偏好均匀随机，未针对基线调先验。
- 先按用户汇总，再按 seed 汇总；配对差使用相同 seed 的 Context-Latest。2,000 次 seed-cluster percentile bootstrap；单 seed 不报告 CI。不把时间步当独立样本，不把 10 个种子当作充分覆盖所有真实用户。

## 5. 下一步：真正可训练的控制器

以下是**待实施方案**，不是已经实现的能力。

### 最小实现

先保持固定槽和类别信念，使用共享小 MLP 输出写入/遗忘门，不增加动态拓扑：

```
r_t = (1 - g_forget) * b_(t-1) + g_forget * uniform
b_t = (1 - g_write) * r_t + g_write * report_distribution
```

输入仅允许现有信念、反馈编码、报告是否存在、熵、可观测冲突、近期证据、距上次观测时间和范围证据。没有反馈时不伪造监督，不把“无纠正”自动当作偏好确认。已知本轮范围使用全方法共享规则。再加相同参数/状态预算的 GRU，区分门控是否需要额外短期证据记忆。

**离线慢学习**：通过跨用户 episode 的未来预测损失训练控制器；**在线快学习**：固定控制器参数，更新每个用户的信念/隐状态。这与“用户每次反馈都反传微调大模型”完全不同。

### 训练监督边界

1. 第一阶段可以用训练模拟器的隐藏状态监督未来预测，但必须显式标记为 privileged synthetic training；隐藏状态不能进入模型特征，也不能在验证/测试时用于在线更新。
2. 基线超参数允许使用同等训练/验证信息和搜索预算；在验证集确定一套部署参数，而不是用测试场景真实噪声率逐场景设定。
3. 第二阶段改为未来可观测报告的似然目标，并考虑报告噪声、范围和反馈选择机制；直接拟合当前噪声报告会奖励错误写入。
4. 如果过程恰好满足已知 HMM 假设，精确 Bayes 滤波已是相应概率损失的最优参照。神经方法的合理机会是未知/非平稳噪声、层级相关性和模型失配，而不是必须击败一个理论上充分的信息最优估计器。

### 正式评估前锁定

- pilot seed 0–9 已用于探索，不再当盲测。建议训练 seed 1000–1019、验证 2000–2009、最终测试 3000–3019，并使用不同 split 名称；仅划分 seed 还不够，要隔离生成参数和用户实例。
- 加入随机变点/持续时间、未见漂移速率、任务内漂移、渐变、相关噪声、任务闲置后返回、未知任务的新槽适应；不要只学习固定第 200 轮反转。
- 新任务键可建槽，不等于理解了新任务的语义；将结构复用与语义迁移分开报告。
- 预先指定主指标和实际意义阈值，例如稀疏噪声下隐藏准确率至少提升 1 个百分点且配对 CI 下界大于 0，同时干净静态条件不显著退化；这是建议，需在盲测前冻结。
- 参照方法由验证集选择，不用测试集挑冠军；多场景/多指标的结论考虑多重比较，pilot 的 CI 只作描述。
- 对照固定写入率、固定遗忘率、无证据历史、无上下文、无范围；记录门控轨迹，但不要把门值可视化直接当作因果解释。
- 单独做闭环：共同外生用户世界与独立固定随机通道，但反馈可以随候选行为变化；如实报告观测数量和选择差异，不能强行称“相同反馈”。

在这些检验之前，暂不推进 Hypernetwork 扩层、App 化或自主拓扑。若 MLP/GRU 不胜出，先检查可观测信息、问题分布与强基线是否已足够，而不是马上堆更复杂网络，或据一次失败终止整个研究方向。
