# B1.3：可训练记忆控制器实验协议

日期：2026-11-09。本文件在本轮正式训练/测试前写入；代码还会在 fit 开始时写出 `design.json`，完成验证集选择后写出 `selection.json`。**fit 不生成测试数据，test 不训练或选模型。**

## 研究假设

一个跨用户训练的小型控制器，能否仅根据已有信念及当前可观测报告，学习比固定写入/遗忘率更好的更新规则？

首轮只验证结构化模拟环境中的机制，不宣称自然语言理解、真实用户泛化、闭环个性化或自主拓扑生长。

## 模型

每个任务的每个维度保存类别信念 `b`，只对具有非本轮范围报告的维度更新：

```
r = (1 - forget) * b + forget * uniform
b_new = (1 - write) * r + write * one_hot(report)
```

没有报告或报告明确只适用于本轮时，信念、证据次数、证据时间和 GRU 隐状态都不更新。缺失反馈不视为赞同。当前轮明确指令由所有方法共有的输出覆盖规则处理，不作为长期状态真值。

这也限制了本轮能力：遗忘门只在有效报告事件时工作，尚未学习“无反馈期间自主衰减”，其概率校准可能因此弱于带显式时间转移模型的滤波器。

门控特征有六个：报告值的已有概率、最大类别概率、归一化熵、对数证据次数、距上次有效证据时间的对数、类别数。没有绝对轮次、任务语义 ID、维度 ID、用户 ID、场景名、真实噪声率、漂移时刻或隐藏状态输入。类别数可以区分二元与三元槽，但不能直接区分 verbosity 与 emoji。

- **MLP**：共享 `6 → 16 → 2`，Tanh + Sigmoid，146 个参数。
- **GRU**：共享 GRUCell，输入 6、隐状态 8，线性门控头，402 个参数。
- 参数跨用户共享；在线推断时不运行优化器，每个用户状态独立重置。
- 类别置换等变，任务名只用于路由；按每条 episode 的首次出现顺序映射到最多 4 个槽区。改名不代表理解了未知任务的语义。
- 上述双门更新形式仍是人为指定的归纳偏置；学习的是门值策略，不是任意拓扑或完全无约束的记忆机制。

### 容量披露

四个任务 × 三个维度，类别信念逻辑上 28 个浮点数，实现中补齐到 36 个。另有 12 个证据次数和 12 个时间值，均 float32：

| 方法 | 共享参数 | 每用户张量状态 |
| --- | ---: | ---: |
| MLP | 146 | 60 个 float32，240 字节 |
| GRU | 402 | 156 个 float32，624 字节 |
| ConstantGate | 2 个固定门值参数 | 与 MLP 相同的状态布局 |

不含 Python/Torch 对象、字符串路由和运行时开销，不能等同真实进程占用。GRU 比其他基线多短期隐状态，**不是严格等字节实验**。ConstantGate 用相同信念表示和同样的计数/时间状态实现，用于检验条件门控是否优于两个固定标量。

## 离线训练监督与信息边界

- **privileged synthetic training**：在训练模拟器中，使用每轮收到反馈前的长期状态预测 NLL 作为损失；模拟器隐藏标签只进入离线损失。
- 当前轮反馈在评分后才更新状态，因此不能用当前报告预测同一轮标签。
- 完整 300 轮 BPTT，Adam，学习率 0.003，梯度范数裁剪 1.0，batch 64，12 epoch；CPU 单线程，启用确定性算法。
- 三个独立初始化 `17, 29, 43`，MLP 和 GRU 各训练三次。所有参数更新量、训练曲线和 checkpoint 哈希保存。
- 每次训练根据验证集宏平均 hidden accuracy 选择 epoch，NLL 仅打破并列；不根据测试结果延长训练、改目标或选择初始化。
- 家族主结果是三个初始化的指标算术平均，不是最佳 seed，也不是预测集成。每次初始化的独立结果同时保留。

## 数据划分

| 划分 | 数据种子 | 用户/种子/场景 | 场景数 | episode 数 |
| --- | --- | ---: | ---: | ---: |
| train | 1000–1019 | 4 | 5 | 400 |
| validation | 2000–2009 | 4 | 5 | 200 |
| test ID | 3000–3019 | 10 | 5 | 1000 |
| test OOD | 3000–3019 | 10 | 3 | 600 |

所有 episode 为 300 轮，split 名称也不同。pilot 数据种子 0–9 不参与此轮训练或验证。

同一 split 内，同一 `(seed, user)` 的用户世界在不同场景中共享基础抽样，因此 400 条训练 episode 不等于 400 个完全独立用户。训练、验证、测试分别对应 80、40、200 个用户世界；统计按数据种子聚类，而不是把场景和轮次当成独立样本。

ID 场景沿用共同回放 pilot 的五类。OOD 场景在训练/验证中均不出现：

1. `ood_noise35`：报告率 0.3、噪声率 0.35，一次突变。
2. `ood_sparse10`：报告率 0.1、噪声率 0.2，一次突变。
3. `ood_renewal`：报告率 0.4、噪声率 0.1；每全局轮次以 0.08 概率随机挑选一个任务和一个维度，将持久值改为不同值。事件数量、受影响任务、维度和时间随机，没有训练中的统一 verbosity 反转时间结构。

OOD renewal 仍是合成分布；它不等于所有未见用户变化模式。测试集用户实例未见，但偏好类别表和任务容量已知，语言/语义迁移没有在此完成。

## 基线选择

Latest 无可调参数。其他每个家族各预先列出 12 个候选，全家族统一按验证集宏平均 hidden accuracy 选一套全局参数，NLL 打破并列：

- DiscountedCounts：`discount ∈ {0.9, 0.95, 0.98, 0.995}` × `prior ∈ {0.1, 0.5, 1}`。
- Delta：`eta ∈ {0.1, 0.25, 0.4, 0.7}` × `decay ∈ {0.95, 0.99, 1}`。
- HazardFilter：`hazard ∈ {0.001, 0.005, 0.02, 0.05}` × `noise ∈ {0.05, 0.15, 0.3}`。
- ConstantGate：`write ∈ {0.1, 0.25, 0.5, 0.85}` × `forget ∈ {0, 0.02, 0.1}`。

基线也获得验证集隐藏标签进行离线评分；部署时不能读真实噪声参数或场景配置。参考方法是在验证集上表现最好的一个全局基线，测试时不重新选冠军。

12 个候选与每次神经训练的 12 次 epoch 验证只是透明的有限搜索预算，**不是严格等 FLOPs/等调参自由度**。神经家族有三个初始化，训练消耗更大，不能仅以候选数宣称成本相同。

## 预先锁定的分析

- 主端点：五个 ID 场景等权宏平均长期状态准确率，相对验证集选定的全局基线。
- 主控制器家族同样在验证阶段按三个初始化的平均准确率选定（`selection.json` 的 `ablation_family` 字段）；另一个家族作为对照，不在测试后重新挑选神经冠军。
- 实际意义门槛：提升至少 1 个百分点，同时配对数据种子聚类 bootstrap 的 95% 区间下界大于 0。
- 同时检查静态干净场景是否退化、单场景结果、Brier/NLL、实际损伤、连续三次任务访问的恢复率及未恢复事件。高平均准确率不能代替恢复速度。
- 聚类单位为 20 个数据种子，种子内包含所有用户和同源场景；控制器家族先平均三个初始化。区间**未完整包含训练随机性的总体不确定性**，独立初始化结果不能隐藏。
- OOD 与消融是次要/探索性分析，不事后改为主指标。不做多重比较校正，不能根据任意一格显著就宣布成功。
- 这是代码内的预先锁定与研究记录，不是外部注册的确认性试验；仍需独立复现实验。
- 根据验证集平均成绩选定一个控制器家族，测试时对其全部三个初始化施加 `no_forget`；若是 GRU，再做 `no_history`。这是未重训的推断干预，只用于机制诊断。

## 执行与审计

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m personal_cortex_lab.train_memory_controller fit \
  --output results/b1_3_controller_fit
.venv/bin/python -m personal_cortex_lab.train_memory_controller test \
  --fit results/b1_3_controller_fit --output results/b1_3_controller_test
```

输出目录必须不存在。test 会先核验源文件和所有 checkpoint 的哈希与 fit 阶段一致，再创建测试数据；变更代码后不能静默复用已锁定实验。

保存训练/验证/测试 episode、测试逐步预测与门控数组（NPZ）、逐用户指标及恢复记录、全部验证候选与训练曲线、紧凑汇总和来源元数据。大体积产物本地保留但忽略 Git；摘要和选择记录可版本管理。

回归测试验证：真实梯度和参数变化、真值不进入公开输入、未来反馈不影响前缀、任务改名/类别置换一致、在线不改控制器权重、在线适配器与批量推断一致、缺失/临时报告不写长期状态、checkpoint 可恢复、数据划分不重叠，以及 OOD 变化确实发生。
